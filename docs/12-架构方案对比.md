# 架构现状与方案选择（v2，2026-10-21）

> 背景：用户简化需求 —— 去掉悬停卡片、HUD 悬浮、全屏隐藏、鼠标穿透；状态栏只显示**一个设备图标**；字体优化；主窗口可自由缩放；加设备探测入口。

## 1. 当前实现的架构（方案 A 的形态）

```
┌────────────────────────── 主进程 main.py（常驻，单实例）──────────────────────────┐
│ 主线程：Win32 消息循环                                                            │
│   ├─ 任务栏单环叠加窗口（UpdateLayeredWindow + GDI+，贴 TrafficMonitor 左侧 6px）    │
│   ├─ 托盘图标（Shell_NotifyIcon，可隐藏）+ 右键菜单                                │
│   ├─ 定时器：布局重算 / 任务栏重建 / 配置重载广播                                  │
│   └─ 窗口过程：左键刷新、右键菜单、双击打开主窗口                                  │
│                                                                                    │
│ 后台线程：每 5 秒 devices.reader.read_all()  ──PostMessage──▶ 主线程刷新 UI         │
│   └─ devices/：ROG OMNI(0x0B05:1ACE) / 罗技 HID++(0x046D:*) / 标准 HID / 蓝牙 → Reading │
└───────────────────────────────┬────────────────────────────────────────────────────┘
                                │ 配置：%APPDATA%\PeripheralBattery\config.json
                                │ 消息：RegisterWindowMessage("PeripheralBattery_Reload")
┌───────────────────────────────▼────────────────┐   ┌──────────────────────────────┐
│ 主窗口进程 ui/panel.py（按需启动，tkinter）      │   │ scripts/                      │
│ 设备页 / 设置页 / 关于页，可自由缩放             │   │ install/uninstall/run_hidden  │
│ 保存 → 写 config + 广播 reload                  │   │ 启动文件夹自启（pythonw）      │
└─────────────────────────────────────────────────┘   └──────────────────────────────┘
```

**为什么这样分**：
- 任务栏叠加窗口 + 托盘图标必须有一个自己控制的 Win32 消息循环；
- tkinter 有自己的 mainloop，和自建 Win32 窗口混在同一进程里容易出现"消息泵互相抢/事件丢失"，实测成本高；
- 两个进程通过 `config.json + 广播消息` 解耦，最简单可靠（参考项目也是这个做法）；
- 全程零第三方依赖：Python 3.12 + ctypes + tkinter。

## 2. 三个候选架构

| | A：双进程（当前，推荐） | B：单进程 + 纯 Win32 自绘 | C：极简托盘 |
|---|---|---|---|
| 进程 | 常驻进程 + 按需主窗口进程 | 1 个进程 | 1 个进程 |
| 主窗口技术 | tkinter（现成控件、可自由缩放） | GDI+ 全部自绘 | 无主窗口或极简 |
| 任务栏圆环 | 有（单设备，圆圈动画） | 有 | 无 |
| 托盘图标 | 有，可隐藏 | 有，可隐藏 | 有（每设备/单设备） |
| 交互/输入法/无障碍 | tkinter 现成 | 全部自己写 | 系统原生 |
| 开发量 | 1×（已过大半） | 2–3× | 0.3× |
| 风险 | 低（双进程约定清晰） | 中高（控件细节坑多） | 低 |
| 观感 | 统一可控（圆环是自绘，窗口是 tk） | 最统一 | 受系统图标尺寸限制 |

**推荐：A**。已实现的模块（设备层、圆环、托盘、启动/配置）可直接复用；主窗口用 tkinter 最省时，且"自由缩放" tkinter 支持得最好（grid 自适应 + 滚动）。

如果更看重"极简、不要圆环动画、只要托盘图标"，选 **C**（工作量最小，但 16px 图标数字看不清、可能被收进"隐藏图标"）。
如果坚持单进程 + 完全统一的深色自绘界面，选 **B**（开发时间约 A 的 2–3 倍）。

## 3. 本次需求变更的落地（进行中）

1. **去掉**：悬停卡片（ui/hover.py）、HUD 悬浮降级、全屏自动隐藏、鼠标穿透；设置页对应开关一并删除。
2. **单设备图标**：叠加窗口只画 1 个圆环；`config.primary_device` 指定显示哪台（空 = 自动选电量最低的一台）。
3. **字体优化**：圆环数字 Segoe UI Semibold、字号 ≈环径×0.36（30px 环 → 11px，不再是 9px）；GDI+ ClearType/GridFit；主窗口统一 Microsoft YaHei UI 10pt、标题 15pt 加粗、正文最小 9pt，去掉 8px 小字。
4. **主窗口自由缩放**：resizable，最小 480×560；设备卡片拉伸、设置页单列 + 滚动、按钮自适应；窗口尺寸/位置记入配置。
5. **设备探测入口**：主窗口设置页/关于页加快捷按钮，启动 `probe.py`（独立进程）。

## 4. 需要用户确认的问题

1. **"状态栏单个设备图标"的位置**：① 任务栏里 TrafficMonitor 左侧的圆环（保留圆圈动画，推荐）　② 通知区域托盘图标　③ 两者都放但都只显示一台设备
2. **多设备（键盘 + 鼠标）时显示哪台**：① 自动选电量最低的（推荐）　② 固定指定一台（设置里选）　③ 并排显示多个图标（又变回多环）
3. **主窗口缩放方式**：① 自由拉伸 + 布局自适应（推荐）　② 整体等比缩放（像网页 zoom）　③ 固定尺寸 + 滚动
4. **架构选型**：A（推荐）/ B / C
